# GROOVETOWN-004 — The Reciprocity Reactor

A **review-only, source-bounded, explicitly fictional** experiment showing how several independent towns can jointly achieve more than one local goal without pretending that claimed resources, offered skills or signatures amount to proof of real-world work.

## Why it is different from GROOVETOWN-003

GROOVETOWN-003 solves one goal with a bounded resource/transport/process model. GROOVETOWN-004 uses the **actual 003 scenario sanitizer**, then executes a new multi-goal bounded search **against one shared inventory**. A resource can be reserved for a satisfied goal only once, process and route quotas are consumed, and a second need cannot quietly reuse the same inputs. It executes the **actual GROOVETOWN-002 Particularity compiler for both recipient needs**, which still holds scheduling and contact details.

The fictional example: Millford supplies 6 kg flour and wants two working lamps. Lantern Town supplies two broken lamps and wants 12 loaves. Ovenham claims a bread process and a lamp-repair process. Bridgeport offers four separate capacity-limited routes. The bounded model finds a conditional, eight-stage plan satisfying both resource targets. Bridgeport and Ovenham provide capabilities without modeled returns: neither is falsely credited with a return. Instead, the generator asks them what voluntary value or terms would make their participation worthwhile. There is **no assertion of overall fairness, compensation, or social benefit**.

The second demonstration subtracts the Ovenham→Millford lamp route and recomputes feasibility: only the bread goal remains feasible. The missing-link enumerator independently derives an Ovenham→Millford lamp-link candidate from a declared process output and a still-unfulfilled goal. Given a **clearly labeled hypothetical** replacement for that specific missing route, it re-solves and shows an additional conditional goal. This is a proposal for *what to ask about*, **not** proof that the missing capability exists or that any named entity offered it.

All inventory quantities and transformations are fictional fixture math, **not food preparation, logistics or repair instructions**.

## Run (Node 20+, zero dependencies)

```sh
node --test experiments/groovetown-001/groovetown.test.mjs experiments/groovetown-002/particularity.test.mjs experiments/groovetown-003/intertown.test.mjs experiments/groovetown-004/reciprocity.test.mjs
node experiments/groovetown-004/reciprocity.mjs demo /tmp/groovetown-004
# Open /tmp/groovetown-004/index.html in a browser. No network required.
```

The demo contains automatically inferred but unverified route candidates, source-bound local work orders, potential recipients and uncompensated participant questions, missing-organ what-if outcomes, independent synthetic NO and ALL YES decisions (which remain field HOLD), and SHA-256 receipts for every generated file. Running twice and comparing exact files must reproduce the same bytes. It does not have real live data, source-native Garden/reLATTE/planZ execution, cryptocurrency, actual operations, deployed notifications, music rendering, or hardware execution. No one has been contacted or consented. No automatic execution of generated work orders is supported.

## Mechanical proof boundaries

- Imported and executed CANNON GROOVETOWN-001/002/003 modules, plus new CANNON-authored 004 search. The 003 original production owner adapter **does not magically become native reLATTE/Garden** through composition.
- The 003 sanitizer validates resource units, quantity, source IDs, visibility, owner, and `PROPOSAL_ONLY` authority; 004 discards private/no-use source claims before outputs and digests.
- Search is finite, modeled in declared units, no inferred transports/conversions. Its `NO_GOALS_IN_BOUNDED_MODEL` is only a statement about this input and search bound; `SEARCH_LIMIT_INCONCLUSIVE` exists for timeout/budget.
- A goal is reserved by consumption in the hypothetical ledger. A returned conditional plan cannot be dispatched. All partner decisions are local fictional simulated strings, not signed identity-verified consent.
- Unmodeled equity and net benefit remain open. Asking each contributor about voluntary terms is mandatory before any serious use; even unanimous yes remains zero real-world credit.
- Source labels and plan digests enable repeatable inspection **not** field verification, witness truth, or authenticated commitments.
