# GROOVETOWN-005 — The Impossibility Foundry

**Review-only, explicitly fictional bounded invention experiment.** A conditional cooperation plan is missing one transport capability. This experimental compiler attempts to construct a possible replacement from a multi-input material dependency chain, instead of inserting a free hypothetical route.

## What changed from 004

004 proved that, **if** Ovenham→Millford lamp transport existed, another declared goal becomes feasible. 005 starts without that route and requires a shared-ledger chain: two wheel blanks (Millford) → fabricate one wheelset → transport wheelset to Ovenham → combine wheelset with a frame (two-input assembly) → activate a hypothetical Ovenham→Millford lamp route → transport three repaired lamps → reserve lamps for two **distinct** declared needs. The 004-native existing bread goal remains in the same ledger; materials, transport capacities, process runs and goal consumption cannot be reused.

This is deliberately toy arithmetic, **not engineering instructions**. A wheelset and frame do not actually certify load capacity, a roadworthy cart, a human carrier, legal use, or safe lamp transport. The invented route is a hypothetical *model capability* with `PROPOSAL_ONLY` authority. No real person is committed, no physical work has occurred.

## Actual measurable results from declared fictional fixture

- Original GROOVETOWN-004 solver without the invented route: **1 / 3 goals conditionally reachable**.
- New 005 extended shared-ledger solver with the component production and route activation: **3 / 3**; two independently declared lamp needs newly reachable; 12-stage causal sequence.
- Subtract either the cart assembly recipe, two wheel blanks, or wheelset transport: **1 / 3**. Every ablation is recalculated, not a display-label substitution.
- Build requires multi-input material at the correct town and consumes the quantities; an invented route cannot activate before construction; no transport beyond its capacity.
- Native 004 `sanitizeReactor`, `solveReciprocity`, and `discoverMissingRoutes` are **actually imported and run**. 005 is a new CANNON-authored hypothetical manufacturing extension; this is **not** yet original source-native execution from reLATTE, Garden, planZ, GHoT or a physical maker.

The standalone offline HTML view compares separately searched outcomes. `01-invention-report.json` lists selected stages, source refs, owners, all HOLD questions, bounded proof scope, dependency graph and the currently unrendered musical idea. `02-admitted-synthetic-input.json` includes only SHARE-scoped declarations. `03-materials-and-dependencies.json` is a static precursor graph: it does **not** establish material access or physical validity. `04-necessity-ablations.json` stores recomputed controls. A SHA-256 receipt covers all generated files. Independent builds must be byte-identical.

## General-purpose interface vs fixture boundaries

`sanitizeFoundry(scenarioWithRecipes)` validates supplied town/resource/process/route declarations through the actual 004 sanitizer, then admits only separately declared `SHARE` and `PROPOSAL_ONLY` recipes. Recipes can consume 1–4 typed material inputs at one known town, create a material output or conditionally enable one invented directed route. Every newly enabled route must match a resource/target gap independently inferred by the original 004 gap discoverer. `solveFoundry` searches inventory, existing processes, declared routes, multi-input construction and enabled invented transport in one finite state space. `compileFoundry` also runs the original 004 baseline and supports optional explicitly selected ablation IDs. The demo chooses three material dependencies to remove as controls.

The search is bounded by number of states and stages. When bounds are reached before success, it reports `SEARCH_LIMIT_INCONCLUSIVE`, **not** global impossibility. Recipe prerequisite graphs can be cyclic; a printed dependency edge is not evidence that an actual path can be executed. The search does not model costs, time, scheduling, safety, emissions, partner terms, human labor, alternative construction techniques, permissions, physical material qualities, or willingness to perform work.

## Strict limitations

- Synthetic source labels and repeatable hashes **do not** establish verified inventory or a physical witness.
- No invention is claimed to have been manufactured, permitted, load-tested, deployed, delivered or consented to.
- No actual value, equity, time savings, cost or return has been measured. Owner questions are **unsent**.
- An imaginary capability does not become real because a solver can hypothetically construct it.
- 005 never posts to an inbox, contacts anyone, spends money, or dispatches work. Human field gates remain outside the execution environment.
- Nothing is merged, promoted to operational canon, or deployed by this experiment.
