**Draft stacks:** CANNON PR #82, originating from truth-first CANNON PR #81; National Treasure original Question Box draft PR #85 stacked on #70; original Iron Lung independently implemented Q-CYCLE-001 (CANNON pins exact reviewed original commit `307754cfe5c4fb0ca5cae7f50073961a761d3d28`).

## Executive behavior

```text
ORIGINAL NATIONAL TREASURE QUESTION BOX
       ├── recoverable real CANNON adapter → chronology question
       └── hypothetical removed adapter → missing source question
                    ↓
ORIGINAL IRON LUNG (Google FLAN-T5 Small)
       3 breaths × Substance → Lineage → Requirements
       9 strictly held proposals per original question
       18 original source-owner generated candidates, none executable
                    ↓
ORIGINAL CANNON SOURCE-NATIVE TEST
       existing adapter passes only with explicit local synthetic grant
       original two native capabilities execute and cold replay
       absent/direct-only adapter HOLD even with provided grant
       model never selects execution, authorizes a grant, or writes software
                    ↓
ORIGINAL NATIONAL TREASURE QUESTION BOX AGAIN
       ├── recoverable source + dated source commit → next counterevidence question
       └── unsupported hypothetical case → still missing source question
```

This is a **replayable workflow, not an autonomous learning system**. It does not recursively schedule itself, automatically accept generated answers, amend private records, or execute on external events.

## Genuine source inputs and strict provenance

The canonical CANNON original Reflex Composer registry supplies the verified `SOURCE_PROOF` → `VISUAL_STUDY` typed adapter. The source port is `cannon.reflex-memory/v1`, the receiver port is `planz.generated-plan/v1`, and the original known adapter is `VERIFIED_RECEIPT_PLAN_ID_V1`, binding `reusableRecipe.planId`. Direct port types are incompatible.

The first NT source has a recoverable location at original CANNON commit `932c3400903123630d1dc6957ee38ae955944930` plus its original file digest, with a single original source family. The second NT source is an *explicit counterfactual*—the known adapter is intentionally withheld—and has NO original source locator. Its provenance remains speculation and support unsupported.

The original NT `buildQuestionFrontier` produces terminal `national-treasure.question-receipt/v0` objects. Those questions are retained unchanged and their SHA256 hashes become source identities when passed to the original Iron Lung code. Iron Lung builds **nine nested model requests per unanswered question**, each with 2–3-word lines, actual source clue/question content, and a parent link to the previous candidate. Model responses are only `POSSIBILITY_UNVERIFIED`; no generated text creates evidence, permission, executed code, or the next question.

A separate *previously authorized* CANNON original native proof is cold-replayed in full through `truth-first-compiler.mjs verify`, proving two actual original native stages. Its video SHA256 outputs and exact typed handoff are validated by the original composer. The model proposal contents play **no role** in choosing the plan, registered adapter, authorization or actual source code. The counterfactual direct-only path stays HOLD and does not execute.

## How the new question arises

We inspect **one dated original Git committer observation**: commit `932c3400903123630d1dc6957ee38ae955944930` at `2026-10-29T19:38:37.000Z`. This is a verifiable source-code observation **not a proof of the earliest appearance of an interface**. The dated observation fills the Question Box chronology slot *for the inspected source*, moving that source's research frontier from `chronology` to `counterevidence`. We preserve a separate explicit nonclaim about historical first occurrence.

The counterfactual has no recoverable source or chronology; it remains at `source-object`. The successful native real case **does not prove the counterfactual exists** and cannot promote it.

The next questions are created by the **actual original National Treasure engine** and are still unanswered. The generated candidate proposals from Iron Lung cannot cause an aperture jump. We record this boundary in `cycle-receipt.json`.

## Reproduce from original repositories

The CI workflow `.github/workflows/inspand-012.yml` checks out the original native owners at their prior verified exact commits (planZ, Haunted Toaster, PlayDeck, Haunted Blender, band-runtime, lemonPRESS), original National Treasure Question Box and original Iron Lung. It runs original source tests and the previous proven CANNON native composer, then separately fetches the real pretrained original FLAN-T5 Small CPU model. Finally:

```bash
node scripts/question-experiment-loop.mjs inspect

  --treasure "$PINNED_NATIONAL_TREASURE" \
  --lung "$PINNED_IRON_LUNG" \
  --provider flan \
  --native "$ORIGINAL_VERIFIED_CANNON_NATIVE_PROOF" \

  --roots "$PINNED_OWNER_MAP" \

  --treasure "$PINNED_NATIONAL_TREASURE" \
  --lung "$PINNED_IRON_LUNG" \
  --provider flan \
  --native "$ORIGINAL_VERIFIED_CANNON_NATIVE_PROOF" \
  --plan "$PINNED_ORIGINAL_PLAN_ID" --planz "$PINNED_PLANZ" \
  --roots "$PINNED_OWNER_MAP" --out /tmp/inspand-012
```

Both built artifacts and verification rerun original source-owner software; bitwise repeatability of greedy FLAN is demonstrated on the pinned CPU runner only, not guaranteed across every device. Original National Treasure and Iron Lung sources are verified by Git origin, exact owner commit and blob/live bytes.

## Concrete artifacts and honest limits

- `first-questions.json`: original NT receipts, never conclusions.
- `iron-lung-investigations.json`: actual 2×9 model candidate records, all held.
- `original-native-proof.json`: independently verified original two-stage synthetic CANNON receipt.
- `observed-commit.json`: exact inspected source timestamp and its historical limits.
- `next-questions.json`: **original NT** outputs after the observed source/testing evidence; still no answers.
- `cycle-receipt.json`: hashes, original owner identities, successful native execution and explicit no-model-control statuses.
- `review.html`: escaped, inspectable comparison of old vs next questions.

**Does not prove:** generation of a new valid adapter; semantic superiority of FLAN-T5; a new independent source witness; causal history; autonomous loop progression; a finished film; human acceptance; saved user time; publishing, deployment or real-world consequences.

**Next qualifying upgrade:** feed independent real source records, a genuinely failing *new* native test, or an owner-approved adapter candidate to this same cycle. Only an original native test with independent receipts could promote its engineering status. The research question must remain unanswered until appropriate evidence is supplied.
