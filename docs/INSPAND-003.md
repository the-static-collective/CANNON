# INSPAND-003 — Reflex Library (review-only)

## What changed
A typed, owner-local registry in `registry/reflex-library-v1.json` describes TWO **previously proven** synthetic software crossings rather than treating every repository as a working executor.

* `film-press-synthetic-selection/v1`: selected original planZ held plan gates an independent five-owner synthetic native film test; the plan does not shape media.
* `film-press-plan-shaped/v1`: source-linked original planZ questions and four lenses deterministically seed an original Haunted Toaster family; original PlayDeck and Blender generate a real silent 96×64 MP4 whose pixels vary by plan.

Each capability advertises accepted input, source owner, output shape, exact runner, time/expense **not measured**, and rights/HOLD boundaries. Registry membership does not convey permission or prove a real-world effect.

## Operating the reflex
```bash
node scripts/reflex-library.mjs list
node scripts/reflex-library.mjs discover --need 'plan film visual replay'
node scripts/reflex-library.mjs build --capability film-press-plan-shaped/v1 \
  --plan "$PLAN_ID" --planz "$PINNED_PLANZ" --roots roots.json \
  --out /tmp/reflex-first --authorize SYNTHETIC_TEST_ONLY
node scripts/reflex-library.mjs verify --capability film-press-plan-shaped/v1 \
  --plan "$PLAN_ID" --planz "$PINNED_PLANZ" --roots roots.json \
  --out /tmp/reflex-first
```

Discovery uses a plainly declared **literal keyword matcher**, not inferred intelligence, permission, ranking by truth, or automatic execution. Empty search returns empty candidates. Build requires operator-selected capability **and** exact plan identity **and** explicit local synthetic authorization. The original INSPAND runner performs its own pinned-source/ancestry verification and native software execution. Verification reruns the native software, byte-compares outputs and separately checks every library receipt. No shell commands or ports from arbitrary catalog rows can run.

## Reuse and durable local memory

Each completed local run retains the original native bytes plus:
- `library-choice.json` — human/operator specified software route and exact held plan.
- `library-capability.json` — exact registry record and digest, limits and test contract.
- `library-memory.json` — content-addressed software result and **reusable recipe** identifying what must be selected again.

The CI executes the same recipe in two fresh directories, checks both with original code, requires equal output MP4 and memory bytes, and rejects altered memory and wrong-capability replay. This is **repeatable construction**, not a network service, a caching layer, personal memory, human-admitted knowledge or an autonomous agent. Nothing quietly executes later.

It should never execute from the catalog, assume source ownership, or treat a source lock as human consent. A separate source-owned JAR;VIS PR is required for this crossing.
