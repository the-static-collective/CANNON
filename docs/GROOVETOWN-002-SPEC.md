# GROOVETOWN-002 — Particularity Engine (proposed)

The first synthetic proof emits a generic held plan. This independent next branch proposes transforming each unresolved need into a source-bounded, role-targeted output, without inventing people, places or capacities.

## Outputs

* A narrowly scoped work order with who/what/when/where/transport plus explicit unknowns.
* One high-value next question when evidence is missing.
* An opt-in, unsent invitation draft.
* A field receipt that requires an independent witness rather than equating reports with completion.
* A local creative cue derived from need status and locally provided constraints.
* A held, minimum-necessary crossing carrying explicit source and permission labels.

## Proof gates

The same need under different supplied local constraints must yield different useful work and creative scenes; missing context must yield HOLD instead of fictional specifics; private and NO_USE fields must never appear in public outputs; closed needs must not recruit new deliveries. All fictional samples must be visibly marked as synthetic. No autonomous outreach, assignment, money movement, physical action, publication, source-owner authority, or imported deed credit.

This document is a design proposal, not deployed software or native source-owner execution. Review-only; no auto-merge.
